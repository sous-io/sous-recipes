# Drafting and Outward-Facing Actions

When the user asks for a **draft** (a comment, message, ticket, reply, email, pull request or
document), they want to review and iterate on it in chat. Drafting never includes sending.

- Produce the draft in the chat response only. Do not post, publish, comment, edit, send or otherwise
  push it to any external system until the user explicitly says to ("post it", "send it"). This holds
  whatever the project's outward-action settings allow.
- Approval is per artifact and does not carry forward. "Post that one" does not authorize the next.
- A message sent under the user's name matches the recipient: a colleague gets a direct, first-person
  note rather than customer-service phrasing, and a settled matter gets no request for confirmation.
- A pull request's draft is its title and description, shown in full.

Every other outward action (one the user did not ask to draft) follows the project's setting for it,
in the always-loaded "Outward Actions" memory.

After drafting, stop and wait.
